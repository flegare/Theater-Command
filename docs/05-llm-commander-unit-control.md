# LLM Commander Unit Interaction & Bidirectional Control Protocol

This document specifies the **Bidirectional Control Protocol** between the **Ollama Fleet Admiral AI Dashboard** (`http://localhost:3000`) and the **Sea Power Unity Game Engine** via the `SeaPowerPerceptionBridge.dll` BepInEx plugin.

---

## 📡 System Architecture & Data Flow

```
+-------------------------------------------------------------------+
|               Sea Power Unity Game Engine                         |
|                                                                   |
|   [ Units / Missiles / Contacts ]                                 |
|               │                                    ▲              |
|   (1 Hz UDP Telemetry)                     (UDP Order Commands)   |
|   Port 9090 ↓                                      │ Port 9091    |
+---------------+------------------------------------+--------------+
                │                                    │
                ▼                                    │
+----------------------------------------------------+--------------+
|               Node.js Admiral Dashboard Server                    |
|               (admiral_dashboard/server.js)                       |
|                                                                   |
|   • Formats perception payload                                   |
|   • Queries Ollama Admiral AI (Model: llama3)                     |
|   • Dispatches LLM Order JSON to Port 9091 ──────────────────────┘
+-------------------------------------------------------------------+
```

---

## 🔌 Socket Port Assignments

| Port     | Protocol | Direction                    | Purpose                                                                                                         |
| -------- | -------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **9090** | UDP      | Game $\rightarrow$ Dashboard | **Telemetry Feed:** Transmits unit positions, headings, altitudes, layer metadata, and perceived contacts.      |
| **9091** | UDP      | Dashboard $\rightarrow$ Game | **Unit Command Receiver:** Receives JSON order packets generated by the LLM Admiral for live execution in-game. |

---

## 📜 Command JSON Payload Schema

When the LLM Admiral generates an order, the server dispatches a JSON packet to **`127.0.0.1:9091`**:

```json
{
  "faction": "BLUFOR",
  "unit": "USS Oliver Hazard Perry",
  "order": "CHANGE_COURSE",
  "heading": 60.0,
  "speed": 20.0,
  "emcon": "ACTIVE_RADAR",
  "details": "Turn Heading 060 to unmask Harpoon launchers"
}
```

### Supported Command Types (`order`):

1. **`CHANGE_COURSE`**
   - **`heading`** _(float, 0-360)_: New heading in degrees.
   - Adjusts the unit's Unity transform euler rotation vector live in the scene graph.

2. **`SET_SPEED`**
   - **`speed`** _(float, knots)_: Desired speed in knots.
   - Converts knots to m/s ($v = \text{knots} \times 0.514444$) and updates the `Rigidbody` velocity vector.

3. **`SET_EMCON`**
   - Adjusts radar/sonar emission states (`ACTIVE_RADAR`, `SILENT`).

4. **`TRACK_TARGET`**
   - Designates target contact IDs for radar tracking.

## 🛠️ C# Plugin Threading Safety

Because UDP packets arrive on a background socket thread:

1. `PerceptionBridgePlugin.cs` queues incoming JSON strings in a thread-safe `List<string> _commandQueue`.
2. On the next frame of Unity's main thread inside `Update()`, `ProcessPendingCommands()` dequeues the orders and modifies the game object transforms safely.
3. This prevents native multi-threading crash exceptions in Unity's physics and renderer engines.

## 🚀 How to Test Live Unit Interaction

1. Launch **Sea Power** and open scenario `poc_llm_admiral.ini`.
2. Open **`http://localhost:3000`** in your browser.
3. Click **`🧠 Query BLUFOR Admiral`** or **`🧠 Query OPFOR Admiral`**.
4. The dashboard will generate the order payload and send it over UDP port `9091`.
5. Your ship in **Sea Power** will immediately adjust its course and heading live in-game!
